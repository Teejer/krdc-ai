## 1. The garbled typing was KRDC's keyboard layout, not the model

Symptoms from the assistant typing into Windows:

- `reg query "HKLM\SOFTWARE\..."` arriving as `reg quft\windows\windowsupdatre\policies\...'/sc`
  — characters dropped, transposed, segments reordered
- `$w` typed as `4w` (Shift lost: `$` is Shift+4)
- capitals arriving lowercase (`microsoft`, `policies`)
- a stray `é` in typed paths

Cause: our pinned base (5876dc36) still had the upstream bug that maps
`en-us` to **KBD_UNITED_STATES_INTERNATIONAL** in `rdp/rdphostpreferences.cpp`.
The RDP session therefore tells Windows to use the US-International layout,
whose quote/apostrophe/tilde keys are **dead keys**. Every scancode the AI
injects goes through dead-key composition: a dead key swallows the next
keystroke (often the Shift press, hence `4` for `$` and lowercase letters),
accents compose with neighbors (`'`+`e` → `é`), and PSReadLine's redraw makes
the leftovers look reordered. The model output was fine.

Upstream fixed exactly this on 2026-11-09 in **b6755c56** ("RDP: Do not map
en-us keyboard to en-intl"), the new base. Also useful upstream commits now
included: ec766e6f (keyboard layout option that follows this computer) and
cf2a5944 (clipboard text as Unicode).

## 4. HTTP 400 "No tool call found for function call output with call_id"

After the restart, having the assistant run any command failed with
`HTTP 400 ... No tool call found for function call output with call_id
call_...` from the model backend.

Cause: our own history persistence. `save()` wrote tool *results* with their
`tool_call_id` but saved assistant entries as text only — the `tool_calls`
were lost. After reopening a conversation, `buildMessages()` emitted a tool
answer whose requesting call was gone; strict OpenAI-compatible servers
reject that orphan with HTTP 400, poisoning every later request in that
conversation.

Fix (commit b7a33ebe):
- `save()` persists the assistant's `tool_calls`; `load()` restores them.
- `buildMessages()` skips tool results whose id is not in the preceding
  assistant message — this also heals history files written by older
  versions (like ours on disk right now) and pairs cut by the 120-entry
  save window.
- Engine test: the mock server now 400s on orphaned tool results like the
  strict servers; two new tests cover the round trip and legacy cleanup.

Packaged as `pkgrel=39`.

## 5. The click aim-crop was hidden by AutoExecute, not removed

The crosshair crop of where a click lands existed all along — but only
inside the approval bar. With `AutoExecute=true` in krdc
the bar never shows, so the preview never appeared. It was never removed
by the rebase (commits "Show what a pending click targets" and "Keep the
approval preview compact" were always in the patch).

Restored for the auto-run path: `runTool()` grabs the same crop just
before the pointer action lands and attaches it to the tool result entry
(`Entry::aimImage`, display only — never sent to the model, never
persisted). The chat renders it inline under the tool result. Approval
flow unchanged. Packaged as `pkgrel=40`.
